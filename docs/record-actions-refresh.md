# 근무기록 수동 추가·개별 삭제·당겨서 새로고침

## 사용 방법

- 사장님: 출석부에서 날짜와 직원을 선택한 뒤 **선택한 날짜에 추가**를 누른다. 입력창에 선택 날짜·직원이 미리 설정되며, 저장하면 해당 날짜의 목록·달력 기록 수가 갱신된다.
- 사장님: 대상 카드의 **기록 수정 → 이 근무기록 삭제**를 누른다. 최신 직원·출근·퇴근 시간을 확인하고 삭제 사유를 입력한 뒤 **이 기록 삭제**로 확정한다. 같은 날짜의 다른 근무는 유지된다.
- 직원·사장님: **오늘 또는 출석부 탭의 맨 위에서 아래로 당겼다 놓으면** 데이터만 새로고침한다. 선택 날짜와 직원 필터를 유지하며 진행 상태를 표시한다.

## 처리 방식

개별 삭제는 서버의 사장님 권한 검사, 최신 기록 토큰, 명시적 확인과 사유를 요구한다. 확인 중 변경된 기록은 다시 확인해야 한다. 요청 번호를 저장해 응답 유실 후 재시도해도 삭제·감사 이력이 중복되지 않는다. 삭제 전 기록·작업자·사유는 조정 내역에 남으며, 급여 집계와 현재 출근 상태에도 반영된다. 기존 트랜잭션 저장 방식을 사용하며 DB 스키마 변경은 없다.

새로고침은 짧거나 가로 방향인 제스처, 화면 중간의 스크롤, 입력 컨트롤·팝업, 저장·로딩 중에는 시작하지 않는다. 새로고침 실패 시 기존 화면을 유지하고 오류와 재시도 수단을 제공한다.

## 검증

- 기존 28개와 개별 삭제 5개를 포함한 단위 테스트 33개 통과: 권한, 확인·사유, 대상 1건 삭제, 급여 재집계, 감사 이력, 변경 감지, 멱등 재시도, 미퇴근 삭제 후 재출근.
- `npm run verify:record-actions`: Chromium·WebKit에서 수동 추가, 취소, 변경 감지·재확인, 응답 유실 후 삭제 재시도, 다른 근무 보존, 직원 권한, 양쪽 역할/탭 새로고침과 필터 유지, 실패 후 복구를 검증했다. Chromium은 CDP 터치 입력, WebKit은 DOM 터치 이벤트를 사용한다.
- `verify:browser`의 기존 PC·태블릿·모바일 39개 화면과 출퇴근→수정→인정→확인→직원 반영 흐름 통과.
- `verify:mobile`: Chromium·WebKit 각각 208개 화면, 총 416개 검사 통과. 삭제 확인창을 포함해 8개 뷰포트에서 넘침·입력창 가림·헤더 고정·페이지 오류를 검사했다.
- 타입 검사·린트·프로덕션 빌드 통과.
- 실제 모바일 기기 검증은 아니며, 캡처는 Git 제외 경로 `docs/screenshots/record-actions/`에 저장된다.
