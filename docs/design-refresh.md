# 디자인·UX 개선 — 2026-09-28

## 방향

기존 초록색 브랜드와 모든 업무 기능을 유지하면서 사장님은 매장 현황과 확인할 기록을, 직원은 출퇴근 상태와 다음 행동을 먼저 볼 수 있도록 정리했다. 로그인, 오늘, 출석부, 직원, 급여, 내 정보, 입력 팝업에 같은 색상·간격·모서리·버튼 규칙을 적용했다. 외부 폰트나 이미지 요청, 새 런타임 의존성은 추가하지 않았다.

| --- | --- | --- |

| 로그인 | 서비스 안내와 입력 폼의 위계 정리 | 아이디·비밀번호, 샘플 계정, 오류·재시도 |

| 직원 오늘 | 출근 전·근무 중·퇴근 완료 안내, 넓은 출퇴근 버튼 | 출근·퇴근·재출근, 요청 중복 방지, 오늘의 기록 |

| 직원·급여·내 정보 | 정보 카드와 금액·이력의 위계, 화면별 안내 | 계정, 시급·산정기간 이력, 예상 급여와 제외 조건, 비밀번호 변경 |
| 모바일 | 하단 메뉴, 확인 필요 표시, 상단 계정 버튼, 계산시간 별도 행 | 데스크톱의 모든 역할별 기능 |
| 입력 팝업 | 모바일 하단 시트, 넓은 저장·취소 버튼, 짧은 화면에서 헤더·푸터 고정 해제 | 기존 입력값·빠른 선택·계산 미리보기·삭제 확인 |

## 모바일·접근성

- 360px 이하를 포함한 반응형 규칙, 16px 입력 글자, 최소 44px 조작 영역을 유지했다.
- 하단 메뉴와 저장 영역은 기기 안전 영역을 반영한다.
- 근무시간은 좁은 화면에서 출근·퇴근 두 칸과 계산시간 한 행으로 분리한다.
- 사장님도 모바일 상단 계정 버튼으로 기존 비밀번호 변경 기능을 이용할 수 있다.
- 메뉴 이동 시 화면 상단으로 돌아간다. 활성 메뉴는 `aria-current`, 확인 필요 상태는 보조 설명으로 전달한다.
- 기존 팝업의 포커스 제한·복원, Escape 닫기, 움직임 줄이기 설정을 유지한다.

## 검증

- `npm test`: 기존 도메인·초기화 테스트 28개 통과.
- `npm run typecheck`, `npm run lint`, `npm run build`: 통과.
- `npm run verify:api`: 로컬 샘플 서버에서 인증, 직원별 데이터 범위, 금지된 쓰기·급여 접근, CSRF, 동시 요청 중복 방지, 출퇴근·재출근, 수정·인정, 급여 계산, 퇴사 계정 세션 무효화 통과.
- 기존 파일과 동일하게 포맷한 코드를 비교해 데이터 요청·변경, 권한, 계산 로직이 유지된 것을 검토했다.
- 사용자 승인 후 Playwright 브라우저 검증을 실행했다. Chromium·WebKit 각각 184개 모바일 시나리오에서 컨테이너 넘침·입력창 가림·페이지 오류가 없었다.
- 모바일 뷰포트: 320×568, 360×780, 375×667, 390×844, 430×932, 667×375, 390×420, 320×320. 모바일 계정 팝업, Escape 닫기·키보드 포커스 복귀, 로그인 후 상단 이동도 검증했다.
- `verify:browser`: PC·태블릿·모바일 화면 39개 및 직원 등록 → 시급 설정 → 출퇴근 통신 실패·재시도 → 사장님 기록 보정·인정·확인 → 직원 반영까지 통과. 가로 넘침·페이지 오류·외부 폰트 요청 없음, 최소 44px 버튼·16px 입력 글자 확인.
- `verify:attendance-management`: 익일 퇴근·휴게시간·사유 선택·계산 미리보기, 초기화 3개 범위의 미리보기·취소, 오래된 미리보기 차단·재확인, 삭제 및 감사 기록 보존, 빈 범위 비활성화, 직원 접근 제한 통과.
- PC 현황·급여, 모바일 출퇴근·계정 팝업, 높이가 낮은 화면의 입력창 캡처를 직접 검토했다.
- 검증 중 로그인 시 스크롤 초기화와 기존 사유가 있는 입력창의 접근성 라벨을 보완했다. 검증 스크립트는 숨겨진 입력값을 포커스 검사에서 제외하고 수정 사유의 정확한 라벨을 사용하도록 수정했다.

로컬 샘플 데이터와 Windows의 Chromium·WebKit 엔진으로 검사했다. 실제 iPhone·Android 기기 및 운영 DB 검증을 뜻하지 않는다. 캡처·상세 결과는 Git 제외 경로인 `docs/screenshots/`에 보관한다.
