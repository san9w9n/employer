# 출석부 달력과 간결한 기록 목록

- 사장님 출석부와 직원 내 출석부는 한국 기준 오늘이 기본 선택된다.
- 월 달력에서 날짜를 누르면 바로 아래에 해당 출근일의 기록만 표시된다. 익일 퇴근도 출근일에 속한다.
- 이전/다음 달, 오늘, 날짜 직접 입력을 제공한다. 달력의 기록 수는 사장님의 직원 선택과 함께 바뀐다.
- 방향키로 하루/한 주 이동, Home/End로 주의 처음/끝 이동을 지원한다. 선택 날짜와 오늘을 각각 표시한다.
- 기록 추가는 선택한 날짜와 직원을 기본값으로 사용한다. 날짜를 바꿔 저장하면 저장된 날짜의 목록으로 이동한다.
- 오늘 화면의 출석부 바로가기는 오늘·전체 직원으로, 확인 필요 바로가기는 최근 미확인 기록이 있는 날짜로 이동한다.
- 출근/퇴근/계산시간을 모바일에서도 한 줄로 배치했다. 날짜·급여 유형·상태·차감·인정·사유·계산 오류와 사장님 관리 기능은 유지한다.
- 카드가 작아져도 관리 버튼의 높이는 44px을 유지한다. 7열 달력의 날짜 버튼은 작은 화면에서 너비 36px 이상, 높이 50px이다.

## 검증

`npm run verify:calendar`는 로컬 데모 서버에서 직원 20명의 기록을 만들고 Chromium·WebKit, 320/390/1440px에서 양쪽 역할을 검증한다. 날짜별 목록·기록 수, 직원 선택, 빈 날짜, 윤년·연도 경계, 익일 퇴근, 키보드 이동, 추가 폼의 날짜 기본값, 저장 실패 후 재시도 시 저장된 날짜로 이동하는 동작을 확인한다. 이전 카드 CSS 배치와 동일 기록의 높이를 비교한다.

| 화면 | 기존 높이 | 개선 높이 |
| --- | ---: | ---: |
| 320px 사장님 | 418px | 245px |
| 390px 사장님 | 374px | 245px |
| 390px 직원 | 299px | 188px |
| 1440px 사장님 | 357px | 122px |
| 1440px 직원 | 282px | 122px |

위 수치는 짧은 사유가 있는 검증용 완료 기록 기준이며, 긴 이름·사유·오류 안내는 내용에 맞춰 높이가 늘어난다. 두 브라우저 엔진에서 동일한 결과를 확인했다. 실제 모바일 기기가 아닌 Playwright 뷰포트 검증이다. 화면 캡처와 상세 결과는 Git 제외 경로 `docs/screenshots/attendance-calendar/`에 저장된다.

추가로 한국 시각 00:30을 고정하고 브라우저를 하와이 시간대로 설정해, 현지 날짜가 전날이어도 한국 기준 오늘이 선택되는 것을 확인했다. `verify:browser`의 기존 39개 화면과 출퇴근·기록 수정·인정·확인·직원 반영 흐름도 통과했다.

`verify:mobile`은 두 엔진에서 각각 200개 화면(8개 뷰포트)을 검사해 가로 넘침·입력창 가림·페이지 오류가 없음을 확인했다. `verify:attendance-management`의 기록 수정·초기화 미리보기/취소/변경 감지/삭제·직원 권한 검사, 기존 단위 테스트 28개, 타입 검사와 린트도 통과했다.

최종 `npm run build`도 통과했다. 넓은 PC 화면의 관리 버튼은 기록 오른쪽에 배치했다. 빌드된 HTML/CSS/JS를 Playwright 요청 가로채기로 직접 공급하고, 기존 서비스 함수가 만든 로컬 데모 상태 응답을 사용해 320/390/1100/1280/1440px × 두 역할 × 두 엔진(20개 조합)을 추가 검증했다. 이는 서버 없는 최종 빌드 화면 검사이며, API 통합 검사는 앞선 개발 서버 검증 결과를 따른다. 최종 캡처·측정값은 `docs/screenshots/compiled-calendar/`에 저장된다.
